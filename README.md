# Game Trend Radar — Roblox × Steam

Локальный парсер и панель на русском для поиска новых популярных игр, измерения роста и исследования игровых механик. Работает на Python 3.10+ без установки сторонних библиотек, без API-ключей и без входа в игровые аккаунты.

## Запуск на Windows

1. Дважды нажмите **start.bat** в этой папке.
2. Откроется **http://127.0.0.1:8767**.
3. Нажмите **«Собрать данные»**, если в базе ещё нет игр. Первый автоматический сбор начнётся в течение нескольких секунд, если автосбор включён.
4. Оставьте окно программы открытым: по умолчанию сбор повторяется раз в час. Закрытие вкладки не останавливает программу, закрытие окна Python останавливает.

В этой рабочей копии уже есть первый реальный сбор. Файлы данных находятся в `data/`; они не включаются в Git. Если порт занят, используйте `python app.py --port 8768`. Для запуска без открытия браузера: `python app.py --no-browser`.

## Что искать

| Раздел | Что показывает |
|---|---|
| Радар игр | Онлайн, возраст, оценки, измеренный рост, история |
| Новые хиты | Свежие проекты / релизы с заметным онлайном и Roblox Up-and-Coming |
| Ожидаемые релизы | Steam Most Wishlisted в выбранной витрине, дата / окно релиза, изменение места |
| Механики и мета | Новые хиты и рост по механикам отдельно для каждой платформы; примеры и гипотезы прототипов |
| Наблюдение | Игры, выбранные звёздочкой или добавленные по ссылке |
| Журнал источников | Охват каждого сбора, полученные игры, ошибки и частичные данные |

В карточке игры доступны график, наблюдаемый пик, признаки роста, распознанные механики с основаниями, заметки и ссылка на первоисточник. Для Roblox можно вручную указать известную дату фактического запуска.

**Практический порядок:** собирать данные 48–72 часа → смотреть новые хиты → фильтровать рост → открыть несколько игр одной механики → изучить игровой цикл → записать гипотезу → проверить небольшим прототипом. После недели наблюдений появится недельное сравнение.

## Показатели и ограничения

- **CCU** — одновременно находящиеся в игре игроки, не продажи, DAU или уникальные пользователи. Визиты Roblox — счётчик посещений, а не число людей.
- Roblox `created` — дата создания проекта. Она **не доказывает дату публикации**. Up-and-Coming учитывается как отдельный сигнал подборки; точную дату по нему не выдумываем.
- Чужие **точные wishlist Steam недоступны**. Показываем публичное место Most Wishlisted для выбранного региона и категории «игры». Оно не переводится в количество ожидающих, продажи или гарантированный спрос.
- Нет ретроспективной истории до первого запуска. Онлайн сравнивается с ближайшей точкой около 1 ч / 24 ч / 7 дней с допуском ±25% (минимум 5 минут). Фактическое окно видно в карточке и CSV. При нулевой базе процент неизвестен.
- **Взлёт**: прирост CCU за сутки от 30%, абсолютный прирост от 100, текущий CCU от 100. Пороги меняются в настройках. Небольшие случайные скачки не считаются взлётом.
- **Устойчивый рост**: дополнительно последние три точки в пределах 6 часов выше вчерашней базы и покрывают минимум 2 часа. Сам по себе сигнал не отличает органический рост от рекламы или ботов.
- **Возраст для новизны** по умолчанию до 90 дней. Early Access, перезапуски и выход из раннего доступа могут менять смысл даты в Steam.
- **Сигнал 0–100** — объяснимая эвристика: 40% размер аудитории (логарифм), 35% прирост (с поправкой на малую базу), 15% свежесть, 10% доля положительных оценок. Для ожидаемых игр другая формула: `80 / rank^0.30` плюс до 20 баллов за улучшение места за сутки. Это не вероятность успеха; сравнивайте выпущенные и ожидаемые игры отдельно.
- Метаданные Steam кешируются на 12 часов, поэтому изменение даты / статуса релиза может отобразиться с такой задержкой.
- Отзывы: используем доступную сводку строки поиска Steam; её язык / регион зависит от витрины. При отсутствии сводки пробуем API отзывов со всеми языками. Область измерения записывается в `review_scope`; разные области не сравниваются. Если API недоступен, повторные обращения отключаются на час. Пустое значение не подменяется нулём.
- Механики определяются **правилами по тегам и словам**, без платной модели. Это классификация с возможными ошибками. Одна игра может входить в несколько групп; суммировать группы нельзя. «Спрос на обеих платформах» означает наличие новых хитов Roblox и новых хитов / ожидаемых игр Steam в группе, а не доказательство причинности.
- Выборка ограничена публичными подборками. По умолчанию до 250 новых кандидатов Roblox и по 25 строк каждой из четырёх лент Steam. Больше можно задать в настройках. Это не полный обход всех игр и не измерение насыщенности рынка.
- Игры из наблюдения собираются независимо от рейтингов; до 300 прочих игр на платформу продолжают отслеживаться 14 дней после последнего попадания в обнаруженную выборку.
- Данные считаются устаревшими через максимум из 3 часов и двух интервалов сбора. Они остаются в каталоге с пометкой, исключаются из сводки механик и сигналов роста.

## Автоматический сбор и экспорт

```powershell
python app.py --collect
```

Один сбор с сохранением в ту же базу. Команду можно использовать в Планировщике заданий Windows с рабочей папкой этого проекта. Создание системного задания не требуется для встроенного автосбора. Сборы из разных процессов не пересекаются благодаря блокировке файла. Код выхода: `0` — без ошибок источников; `2` — частичные данные / ошибки; `3` — сбор уже выполняется.

CSV экспортируется кнопкой **«CSV всех игр»**: UTF-8 с BOM, по всем играм базы, с датой замера, абсолютным / относительным приростом и фактическим окном. Строки защищены от интерпретации названий игр как формул Excel.

База: `data/radar.sqlite3`. Журнал программы: `data/server.log`. Для переноса истории остановите программу и скопируйте папку `data`. Не запускайте разные копии базы как одну историю.

## Источники

Roblox:
- `apis.roblox.com/explore-api/v1/get-sorts` и `get-sort-content`: подборки и кандидаты.
- `games.roblox.com/v1/games`, `/votes`: метаданные и показатели.
- `thumbnails.roblox.com/v1/games/icons`: изображения.
- `apis.roblox.com/universes/v1/places/{placeId}/universe`: ссылка на игру → вселенная.
- [Roblox Discovery](https://create.roblox.com/docs/discovery), [публичные API домена games](https://create.roblox.com/docs/cloud/reference/domains/games).

Steam:
- `store.steampowered.com/search/results/`: `popularnew`, `newreleases` с сортировкой по дате, `popularwishlist`, `topsellers`.
- `store.steampowered.com/api/appdetails`: метаданные.
- `api.steampowered.com/ISteamUserStats/GetNumberOfCurrentPlayers/v1/`: текущий онлайн.
- `store.steampowered.com/appreviews/{appid}` и сводки витрины: доступные оценки.
- `store.steampowered.com/tagdata/populartags/english`: первоисточник для проверки соответствий ID тегов и их названий в правилах механик.
- [Steam Web API: текущие игроки](https://partner.steamgames.com/doc/webapi/ISteamUserStats), [wishlist-отчётность владельца](https://partner.steamgames.com/doc/marketing/wishlist/reporting), [отзывы](https://partner.steamgames.com/doc/store/getreviews).

Витринные и discovery API могут менять формат без предупреждения. Парсер использует таймауты, ограничение частоты запросов, до трёх попыток при временных сбоях и Retry-After. Учётные данные и обход защит не используются. При сбое источника полученные ранее данные сохраняются.

## Проверки и структура

```powershell
python -m unittest discover -s tests -v
node --check web/app.js
```

Node нужен только для необязательной синтаксической проверки JavaScript, для работы программы не нужен. Проверки HTTP используют только временную базу и localhost. Необязательная проверка реального формата использует сохранённые `data/probes/` при их наличии. Для новой проверки источников: `python tools/probe_sources.py`.

```text
app.py              CLI и запуск локальной панели
radar/sources.py    обнаружение и сбор Roblox / Steam
radar/http.py       сетевые ограничения и повторы
radar/db.py         SQLite, история, настройки и кеш
radar/analysis.py   рост, оценки, группировка механик
radar/service.py    сбор и расписание
radar/locking.py    защита от одновременных сборов
radar/server.py     локальный HTTP API
web/               интерфейс без сторонних зависимостей
tests/             проверки расчётов, парсинга и API
```

Панель привязана только к `127.0.0.1`. Это локальный инструмент для одного пользователя; публикация в интернет потребует отдельной авторизации и развёртывания.

## Публичная копия на GitHub Pages

Сайт: https://alcatrezz1.github.io/tracker/

Workflow `.github/workflows/radar.yml` раз в час запускает `python app.py --collect` в GitHub Actions, собирает статичную копию панели (`python tools/build_static.py`) и публикует её на Pages. База хранится в ветке `db` в виде `radar.sqlite3.gz`; ветка перезаписывается при каждом сборе, поэтому история репозитория не растёт. Замеры старше 35 дней удаляются при сборке.

Публичная копия работает только для чтения: сбор, настройки, наблюдение и заметки доступны в локальной версии (`start.bat`). Внеочередной сбор: вкладка Actions → Collect and publish → Run workflow.
